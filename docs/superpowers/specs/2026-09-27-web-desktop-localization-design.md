# Web 与 Desktop 全站中文化设计

## 目标与边界

在 `zh` 和 `zh-hant` 下，将 Hermes 自有的 Web Dashboard 与 Electron Desktop 界面文案完整显示为对应中文，包括导航、设置、对话辅助控件、弹窗、表单、空状态、成功/错误提示、可访问性标签和启动/更新界面。语言切换要即时生效。英文界面不改变。保留专有名称、命令、路径、配置键、用户输入、服务商返回的诊断原文和插件/目录提供的外部内容，不将它们误报为漏译。此次不翻译 CLI、QQBot 的对话内容、第三方插件或在线文档。

`F:\hermes-desktop` 是正在运行的 Electron 安装目录，界面包含在 `resources/app.asar`（2026-09-20）中，不是源代码；真正源码位于本仓库 `apps/desktop/`。Web Dashboard 位于 `web/`，其生产资源为 `hermes_cli/web_dist/`。两端要分别修复和验收，Web 构建不代表 Desktop 安装包更新。

## 方案选择

1. **推荐：源代码补译 + 行为验证 + 独立打包、冷启动、切换。** 在已有 i18n 字典/覆盖层中补译，逐页面接线；新版本构建到独立目录，先在测试数据目录冷启动，再停掉 `F:\hermes-desktop` 的进程、备份旧目录、切换并实测。改动可审查、可回滚。
2. 直接替换当前 `app.asar`：快，但无法保证源码/运行字节一致，运行中替换与原生依赖版本不匹配，拒绝。
3. 只替换 WebUI 静态资源：不影响 Desktop `app.asar`，无法满足此次需求，拒绝。

## 汉化数据流

Web 的 `I18nProvider` 按 locale 选择静态字典；Desktop 的 `defineLocale` 把本地覆盖层叠加英文基准。字典键与类型只是第一道检查。新增文案必须沿现有 i18n 路径传到真实页面，不引入运行时机器翻译、全局硬编码替换、第二套并行字典或额外依赖。

对每个可见路由与典型状态建立清单：首次加载、成功、失败、空列表、编辑与二次确认。页面测试挂载实际组件，至少覆盖简中与繁中，检查可见文本和 accessible name；数据来自受控 API 响应，不窥测源码文本。动态名称、数字及参数必须保留，函数译文类型、参数和占位符不丢失。测试优先覆盖用户报告出现英文的页面；红灯证明问题、最小修复转绿。翻译自然、术语统一，避免把技术标识翻成无法搜索的中文。

后台返回的英文诊断只作为原文附在已本地化的错误提示之后；不伪造服务端翻译。外部技能目录、插件名称、模型名等原始数据保持原样。检查简/繁中时分别设置实际 locale，避免测试仅断言字典对象存在。

## 分阶段交付

1. **审计：** 用页面/状态清单和人工走查识别硬编码、英文回退与打包资源旧版；列出真实缺口而非比较文件行数。保留现有中文扩展键。对桌面包记录 `app.asar` 哈希、进程、版本与用户数据目录。
2. **Web：** 按页面群修复，逐群先红后绿；执行 `npm run check --workspace web` 与 `npm run build --workspace web`，并实际打开 `zh`/`zh-hant` 路由核验典型交互。
3. **Desktop：** 按导航、设置、会话/工具、启动/更新等界面群修复，逐群先红后绿；执行 typecheck、i18n/页面 UI 测试、lint 和生产构建。未通过的无关既有测试要单列基线与影响，不能写作全绿。
4. **本机发布：** 从固定 Git SHA 侧建 Electron unpacked 版本；在隔离的 `userData` 下冷启动，验证启动、语言切换、设置、密钥和核心对话控件。确认未混入旧缓存资源，再停掉现有 Desktop 进程；旧目录保留独立备份，原子切换 `F:\hermes-desktop`，复测并保持当前用户数据与 Hermes 配置/密钥不变。失败则恢复旧目录与进程。
5. **130 发布：** 只发布已经验证的 Web Dashboard 资源；先备份远端 `web_dist`，更新后验证 9119、汉化资源哈希、Gateway 8642 与 QQBot 连接；不因前端翻译重置模型配置或 Python 运行时。失败立即回滚资源。Web 和 Desktop 的 GO 分开报告。

## 完成判据

每个列入清单的第一方界面在 `zh`、`zh-hant` 两种语言的代表状态均无英文回退，允许明确登记的技术标识与外部内容。对应行为测试、类型检查、构建输出与 `git diff --check` 均有实际退出码。Desktop unpacked 冷启动和最终 `F:\hermes-desktop` 的运行版本必须分别核验；本机/130 的 `/health` 与 QQBot 连接不得退化。模型回复测试若因供应商故障失败，要明确标为未验证，不能借 HTTP 200 推断对话正常。所有备份位置、最终 SHA、剩余第三方英文及回滚结果写入交付报告。

## 风险与回滚

完整 UI 覆盖需要按页面群增量验收；不允许一次性生成大量文案直接上线。`F:\hermes-desktop` 正在运行，先冷启动侧装版后才停机切换；不覆盖现有 `AppData\Roaming\Hermes` 用户数据。Windows 进程、安装包签名/分发方式若阻止安全侧装，应停止发布并保留已验证源码，不把 `npm run build` 等同于安装成功。130 的磁盘较满，部署前再次确认备份空间，避免多份完整运行时副本。
